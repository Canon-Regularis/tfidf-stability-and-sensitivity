# Mutants that survive because no behaviour distinguishes them.
#
# A mutation that no test kills is usually a gap in the tests. Sometimes it is
# not: the mutated expression cannot be reached, or reaches the same answer by a
# different route, and no test could tell the difference. Those are "equivalent
# mutants", and they are why a mutation score of 100% is not generally
# attainable.
#
# Without this file the nightly campaign fails whenever any mutant survives,
# which -- with equivalents present in almost every module -- means it fails
# every night regardless of the state of the tests. A gate that always fails is
# worse than no gate: it stops being read.
#
# Format, one claim per line:
#
#     <module path>  <line>  <kind>  <before> -> <after>  # why it cannot be observed
#
# The reason is required. An entry without one is a suppression, not a finding.
#
# Two ways this file fails the build, both deliberate:
#
#   * a survivor that is not listed here -- a real gap, or a new equivalent that
#     has not been justified yet;
#   * an entry here that matched no survivor -- the mutant is now killed, or the
#     line moved, and the claim must be re-checked rather than left to rot.
#
# The second is what stops the file accreting into a blanket suppression. Line
# numbers are part of the key on purpose: an equivalence argument is about a
# specific expression, and if the expression moves the argument needs re-reading.
#
# Known limitation. The key is (line, kind, before, after), and two mutable sites
# on one line can share all four -- `@dataclass(frozen=True, slots=True)` yields
# two identical `constant True -> False` keys. One claim then covers both, so a
# claim written for such a line must justify every mutation that matches it, not
# whichever one was looked at first. The alternative key, a mutation's index in
# document order, is worse: it shifts whenever anything above it is edited, so
# every claim in a file would go stale on an unrelated change.
#
# The scope of a claim is a test set. A mutant that survives one suite may die
# under another, and then it was never equivalent -- it was under-tested. The
# nightly matrix pairs each module with its own suite plus
# tests/test_public_api_surface.py, and the claims below are made against that
# pairing. Measuring against a different one will disagree.
