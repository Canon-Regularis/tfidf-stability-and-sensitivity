# Data

**Nothing in `data/raw/` may be committed.** It is gitignored, and that is a
licence requirement rather than a tidiness preference.

## Layout

| Path | Tracked? | What it is |
| --- | --- | --- |
| `data/raw/` | **no** | Downloaded archives. Fetched on demand, never redistributed. |
| `data/interim/` | **no** | Parsed corpora (`*.jsonl`) written by `scripts/build_corpus.py`. |
| `data/processed/` | **no** | Fitted models (`*.tfsx`) and experiment outputs. |
| `data/assets/` | yes | Small committed fixtures that carry no third-party licence. |

## The two datasets, and why they are treated differently

### `synthetic_small` — redistributable, regenerated on demand

Generated by `tfidf_stability.datasets.synthetic` from a seed and a spec. It is
never stored in the repository because it does not need to be: the spec is 20
lines, and regenerating is faster than reading a file.

This is the corpus CI uses. Everything the study needs can be *controlled* here —
corpus size, vocabulary size, the exact-duplicate count, the twin pairs — which
is exactly what a real dataset cannot give.

```bash
python -c "from tfidf_stability.datasets.loaders import load_dataset; \
           print(load_dataset('synthetic_small').n_documents)"
```

One caveat, recorded as `docs/spec_addenda.md#g22`: the twin mechanism produces
score separations in the **1e−3 to 1e−1** range and cannot go finer. Because
§2.2 normalises `tf = count / L`, a single-token edit is a `1/L` *relative*
perturbation, so a separation of 1e−9 would need a billion-token document. Fine
near-ties are located, not constructed — see `find_near_ties`.

### `movielens_small` — not redistributable, fetched on demand

MovieLens `ml-latest-small`: 610 users, 9742 films, 100,836 ratings.

> The MovieLens usage licence permits research use and **prohibits
> redistribution**. This repository therefore contains the *parser* and a pinned
> SHA-256, and never the data.

```bash
python scripts/fetch_data.py                       # download + verify + pin check
python scripts/build_corpus.py movielens_small \
    --archive data/raw/ml-latest-small.zip \
    -o data/interim/movielens.jsonl
```

**Why the digest is pinned.** GroupLens updates `ml-latest-small` *in place*, at
a stable URL. Without a pin, the corpus underneath a published number can change
with no visible signal at all. `movielens.load` raises `DataIntegrityError` on a
mismatch rather than warning, because a warning is exactly what gets filtered out
by the scripts that most need to see it.

The pin cannot establish authenticity — upstream publishes no digest of its own —
only **stability**. That is the property the reproducibility claim actually needs.

If you must cite it:

> F. Maxwell Harper and Joseph A. Konstan. 2015. The MovieLens Datasets: History
> and Context. *ACM Transactions on Interactive Intelligent Systems* 5, 4:
> 19:1–19:19. <https://doi.org/10.1145/2827872>

## How the fields map onto the model

| Model field | Synthetic | MovieLens |
| --- | --- | --- |
| `text` | Zipf-sampled tokens | title + genres + user tags |
| `popularity` | sampled integer | number of ratings |
| `rating_sum2`, `rating_count` | sampled exact pair | `2 × Σ rating`, count |
| `engagement` | sampled integer | number of tags |

Ratings are stored as the **exact integer pair** `(2 × Σ rating, count)` and
never as a float mean — `docs/spec_addenda.md#g8`. MovieLens ratings are
quantised to halves, so `2 × rating` is always an integer and the representation
is exact on real data, not merely on constructed fixtures. Comparison is by
cross-multiplication, so two distinct means can never collide onto one double.

**18 of the 9742 films** appear in no row of `ratings.csv`. Their mean is
genuinely undefined, so they carry `has_value = False` and sort last — G8's
missing-value path exercised against real data rather than a constructed
fixture. That count was measured against the pinned archive
(`696d65a3…`) on first download, not taken from upstream documentation.

## Reproducing a published number

Every run manifest carries a `provenance` block naming the dataset, and for
MovieLens the archive digest. So a result can be traced to its corpus after the
fact, and `"redistributable": false` marks the ones that cannot be reproduced
from this repository alone.
